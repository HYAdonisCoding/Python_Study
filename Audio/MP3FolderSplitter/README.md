# MP3 Folder Splitter v2.0

把一堆音频按容量重新分装进编号子文件夹的本地整理器。默认目标 **550 MB**、硬上限 **600 MB**，十进制口径，只移动不转码，全程可预览、可追溯、可回滚。

```bash
python3 main.py ~/Music/周杰伦          # 预览 → 确认 → 执行
python3 main.py --gui                  # 图形界面
```

---

## v1 → v2：修掉了什么

v1（`mp3_splitter.py`，保留在仓库里作参考）是一份能跑的单文件脚本。实测和 review 发现的问题，v2 逐条对应：

| # | v1 的问题 | 后果 | v2 的做法 |
|---|---|---|---|
| 1 | 装箱打分用 `abs(new_size - target)`，对目标是对称的 | 每个箱子都被顶到 600 硬上限（实测 14 箱里 13 箱在 598~600 MB），根本不是 550 | 目标容量改为**软上限**：默认任何箱子不超过 target；`--overflow` 才允许填到 max |
| 2 | `MB = 1024*1024` | 标称 600 MB 实际 629 MB，网盘/车机/U 盘按十进制算就超限 | 默认十进制 `1 MB = 1,000,000 B`，需要时 `--binary` |
| 3 | 只搬 `.mp3` | `.lrc`/封面留在原地，整理完一地散件 | 同名伴生文件一起入箱，体积也计入容量 |
| 4 | 目标同名文件直接跳过 | 文件永远搬不走，下次运行又被扫到，死循环 | 自动改名 `名字 (2).mp3`，不覆盖、不丢弃 |
| 5 | 目录参数不去重 | `main.py /a /a` 会生成空文件夹 + 一大批移动失败 | 去重 + 拒绝父子目录同时入选 |
| 6 | `iterdir()` / `input()` 无异常保护 | 权限不足或非交互环境直接 traceback | 全部捕获，给出可读错误和退出码 |
| 7 | `shutil.move` 跨卷非原子 | 中断会留下半截文件 | 同盘 `os.rename`；跨盘先写 `.part` 再 `os.replace` |
| 8 | 无日志、无恢复 | 搬到一半中断只能靠回忆 | `plan.json` + `state.jsonl` 双文件日志，`--resume` 续跑、`--undo` 回滚 |
| 9 | `._xxx.mp3` 被当成真 MP3 | macOS 资源叉混进分箱 | 按前缀过滤 |
| 10 | 预览和执行各算一次编号 | 极端情况下不一致 | 扫描阶段一次算定 `next_index` |

## 功能

| 项 | 说明 |
|---|---|
| 目标容量 | 550 MB（软上限，单箱不会超过） |
| 硬性上限 | 600 MB（判定超大单文件 / `--overflow` 时的上限） |
| 跳过小目录 | 内容 < 600 MB 时自动跳过（`--skip-under` 可调，`0` 关闭） |
| 容量单位 | 十进制 MB，可切二进制 MiB |
| 文件类型 | MP3 为主，`--types flac,wav,m4a` 可扩展 |
| 伴生文件 | 同 stem 的 `.lrc/.txt/.cue/.jpg/.png/.nfo...` 跟着走；目录级 `cover.jpg` 可选复制 |
| 批量目录 | 多个目录一次处理，自动去重、拒绝嵌套 |
| 分组策略 | Best-Fit Decreasing + 收尾救尾巴 |
| 预览 | 每箱容量 / 文件数 / 进度条 / 校验结论 |
| 冲突处理 | 目标已存在自动改名，绝不覆盖 |
| 二次校验 | 输入 YES 之后、动手之前重新 stat 一遍，文件变了就中止 |
| 操作日志 | 每次会话一个目录：计划、逐条状态、汇总、人类可读日志 |
| 中断恢复 | `--resume` 只补没做完的，`--undo` 原路退回并清空目录 |
| 界面 | `--gui` tkinter 界面；装了 tkinterdnd2 可拖拽目录 |

## 命令行

```bash
python3 main.py [目录 ...] [选项]
```

不传目录会打开 macOS 文件夹选择器，可连续选，取消结束。

| 选项 | 默认 | 说明 |
|---|---|---|
| `--target N` | 550 | 目标容量 MB（软上限） |
| `--max N` | 600 | 硬上限 MB |
| `--skip-under N` | 600 | 目录内容小于该容量 MB 时跳过不处理（`0` 关闭跳过） |
| `--binary` | 关 | 用 1024 进制（MiB） |
| `--overflow` | 关 | 允许箱子填到 `--max`，箱数更少但会贴上限 |
| `--no-balance` | 关 | 关闭收尾再平衡 |
| `--sort {size,name}` | size | 装箱排序：`size` 按体积降序（箱数最少）；`name` 按文件名自然排序 |
| `--types mp3,flac` | mp3 | 音频扩展名 |
| `--no-companions` | 关 | 不搬伴生文件 |
| `--copy-artwork` | 关 | 把 `cover.jpg` 复制进每个子文件夹 |
| `--template "{name}{index}"` | 同左 | 子目录命名，必须含 `{index}` |
| `--dry-run` | 关 | 只预览 |
| `--yes / -y` | 关 | 跳过确认 |
| `--json` | 关 | 结果以 JSON 输出到 stdout（人类日志转到 stderr） |
| `--list` | — | 列出历史会话 |
| `--resume [ID]` | — | 续跑，省略 ID 取最近一次未完成 |
| `--undo [ID]` | — | 回滚，省略 ID 取最近一次 |
| `--log-dir PATH` | `./logs` | 日志目录 |
| `--gui` | — | 图形界面 |

常用组合：

```bash
python3 main.py ~/Music/A ~/Music/B --dry-run          # 先看效果
python3 main.py ~/Music/A --target 500 --max 520 -y    # 换目标直接跑
python3 main.py ~/Music/A --sort name --dry-run        # 按文件名自然排序预览
python3 main.py ~/Music/A --overflow                    # 尽量少箱子
python3 main.py --list                                  # 看历史
python3 main.py --resume                                # 中断后续跑
python3 main.py --undo 20261030-152526                  # 撤销那次整理
```

### 批量整理「父目录下的一堆歌手文件夹」

如果歌手文件夹都摆在一个父目录里（比如 `~/下载` 下面是 `周杰伦/`、`林俊杰/`、`刘德华/`…），用 shell 通配符一次展开：

```bash
python3 main.py ~/下载/*/
```

等价于把每个子文件夹单独传进去：

```bash
python3 main.py ~/下载/周杰伦 ~/下载/林俊杰 ~/下载/刘德华
```

两种写法都会把每个歌手文件夹各自按 550 MB 分装成 `周杰伦1`、`周杰伦2`…，互不串箱。

注意：

- `*/` 只展开**一层**子目录，不会继续往下钻；它也不会区分「歌手文件夹」和「已经被工具整理出来的编号目录」，所以如果一个目录下既有 `周杰伦` 又有 `周杰伦1`，两者都会被当成输入——`周杰伦1` 内部通常是空的，扫描后会被跳过，不产生实际影响。
- 不要在 macOS 音乐 App 的系统库目录（`~/Music/Music` 这类，含 `Media.localized`、`Music Library.musiclibrary`）上跑——那是数据库和缓存，不是按歌手摆的音频。

退出码：`0` 成功 · `1` 执行有失败项 · `2` 参数或校验不通过 · `130` 中断。

## 分组算法

1. 文件按体积降序（伴生文件体积先并入所属音频）。
2. **Best-Fit Decreasing**：每个文件放进"放完之后剩余空间最小"的箱子，放不下就开新箱。箱子利用率高、数量少。
3. **收尾救尾巴**：只有最小箱低于 `target × 40%` 才动手，把大箱里的文件挪过去，且大箱挪完不得低于 `target × 85%`——避免把所有箱子拉平成一片 430 MB 的中等箱（那样反而离 550 更远）。
4. 单文件 > `max` 的留在原地并告警；单文件在 `target ~ max` 之间的独立成箱。

实测对比（120 个 6~14 MB 随机音频 + 伴生文件）：

| 版本 | 结果 |
|---|---|
| v1 | 600 / 600 / 600 / 598（全部顶到硬上限） |
| v2 默认 | 536 / 535 / 229（前两箱贴近 550，尾巴箱保留） |
| v2 `--overflow` | 598 / 596 / 400（箱数最少） |

## 日志与恢复

每次执行生成 `logs/<时间戳>/`：

| 文件 | 内容 |
|---|---|
| `plan.json` | 完整操作计划，**动手之前**写盘并 fsync |
| `state.jsonl` | 每完成一个文件追加一行并 fsync |
| `summary.json` | 汇总：移动/复制/失败数、字节、状态 |
| `session.log` | 人类可读的逐条记录 |
| `undo-*.json` | 回滚时生成的审计记录 |

恢复判定规则（宁可不动，也不乱动）：

- 源在、目标不在 → 待搬，`--resume` 处理
- 源不在、目标在 → 已搬完只是状态没落盘，标记完成，不重复搬
- 源在、目标也在 → 不覆盖，按冲突改名

回滚只回退 `move` 操作（`--copy-artwork` 复制出来的封面不动），并把变空的编号目录一并清掉。

## 注意

- **只扫一层**，不递归。已存在的编号子目录不会被重复处理。
- 目录内音频总容量（含伴生文件）**小于 600 MB** 时默认跳过，不做分箱——反正一个箱子也装不满。需要强制处理时用 `--skip-under 0`。
- 编号取「已有最大编号 + 1」，不复用空号，所以中途删过目录会继续往后编。
- 伴生文件靠「同名不同后缀」匹配；目录级 `cover.jpg` 默认不动，需要时 `--copy-artwork`。
- 移动只改路径，不改内容、不改 ID3、不转码。
- 同一目录下如果有 `.m3u` 播放列表，它会留在原地（里面的路径会失效），这是刻意的：播放列表跨箱没有意义。
