## mp4_batch_to_audio.py 增加 LRC 歌词
- 需求：批量转音频时把 .srt 转成歌词文件，播放时同步显示。
- 调研结论：VLC 官方字幕格式列表不含 LRC，Apple 音乐 / QuickTime 不支持 .lrc；最可靠的是 VLC / IINA / mpv 加载同名 .srt 外挂字幕。因此默认同时产出 .lrc + .srt 副本，不做元数据内嵌。
- 脚本重写：新增 `parse_srt()`（解析时间轴）、`make_lrc()`（起始时间生成 `[mm:ss.xx]`，双语默认 ` / ` 合并）、`write_lyrics()`；参数 `--lyrics`/`--no-lyrics`（默认开）、`--lyrics-only`（不转码只补歌词）、`--lyrics-lang all|en|zh`。
- 修复：原逻辑音频已存在就 continue，导致歌词不生成；现把歌词处理提到跳过判断之前，二次运行仍会补歌词。
- 实测（全在临时目录）：27MB 动画 mp4 → m4a 111.316 秒（与 JSON duration 111.32 一致）、40 条 LRC、双语/单语过滤正确；批量 `--lyrics-only` 20 个 mp4 产出 10 组 lrc+srt（精讲无字幕跳过）。
- 环境：ffmpeg 8.1 / ffprobe 在 /opt/homebrew/bin；源目录 20 个 mp4、10 个 srt。未在用户真实目录实际转码。
- README 第 4 节重写，含播放器兼容性表。

## 音频默认格式：m4a 而非 mp3（用户追问）
- 实测这批 MP4 音轨本来就是 AAC 128k / 44.1kHz 双声道。选 M4A 的理由：可无损换容器（`-c:a copy`）、Apple 生态原生、元数据/封面支持好；MP3 必须重编码，是有损转有损。
- 发现并修复旧实现瑕疵：原 m4a 分支用 `-c:a aac -b:a 192k` 重编码，没吃到无损红利，还把 128k 源撑到 192k（体积更大、多一次损失）。
- 单集 111.3s 实测：m4a 无损 copy 1.72MB/0.19s；m4a 重编码 192k 2.60MB/1.57s；mp3 192k 2.55MB/1.56s；mp3 128k 1.70MB/1.33s。
- 脚本改动：顶部新增 `DEFAULT_FORMAT='m4a'` / `DEFAULT_BITRATE='192k'`（改默认只改一行）；`probe_audio_codec()` 用 ffprobe 判源编码；m4a + 源 AAC 时默认无损直拷，非 AAC 自动回退重编码；新增 `--reencode` 强制重编码；日志标注模式。
- 验证通过：默认走无损复制（bit_rate 保持 127999）、`--reencode` 得 194245、mp3 128k 得 128000、mp3 音轨的 mkv 自动回退重编码成功。全在临时目录，未动真实文件。
- README 第 4 节加「为什么默认 M4A」实测表与改默认/切 MP3 的方法；提醒 MP3 建议对齐源 128k，别用 192k 白撑体积。
